# Generation and verification

An actual fresh Codex app agent used `$just-build` for a named CSV Intake Check request. The request fixed the public interface and behavior before implementation: `python app.py check INPUT.csv --json`, exit 0 for valid input and 2 for validation/read failures, structured errors, physical start-line diagnostics and input preservation. Idea discovery was appropriately skipped. This was a supplied evaluation specification, not market validation.

Background and implementation research consulted Python's [CSV](https://docs.python.org/3/library/csv.html) and [codecs](https://docs.python.org/3/library/codecs.html) documentation and [RFC 4180](https://www.rfc-editor.org/rfc/rfc4180). Applied choices included newline-aware reading, UTF-8 signature handling and physical-line tracking.

The completed tracker recorded all stages done, `complete: true`, 13 executions, five research entries and passing Quality, Polish, Security and fresh final verification. Initial and final verification each passed five bound acceptance labels, a frozen six-step external CLI contract and structural checks. The project's five public-entry-point tests cover broader scenarios inside each method. A separate evaluator fixed before the maintainer inspected implementation passed all 11 held-out cases. It now lives in [the repository evaluator](../../tools/evals/csv_intake.py); its cases are public regression coverage after release.

Quality was an actual read-only agent review exercising journey, errors and README examples. A second agent performed Polish. Security reused the Quality identity in a separate disclosed passive role. Thus there were two reviewer identities, not three. A passive six-file scan had zero heuristic findings; one documented minor risk remains: total work and accumulated diagnostics are not capped for large local files. The supported scope is an offline CLI for trusted local inputs. No active penetration testing occurred.

The initial ledger rejected a test script with extra arguments; the rejected attempt was retained. A fresh ledger froze ordinary unittest commands with the same external contract. A premature Security scan was refused by stage ordering and later executed in order. Review-agent limits required sequential reuse. One raw review object was normalized to the tracker schema without changing its conclusions. An account-limit interruption and maintainer helper update were documented. The app was not changed after successful final verification. This is an assisted completed run, not a claim of uninterrupted one-shot completion.
