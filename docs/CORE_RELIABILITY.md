# Core reliability changes

This revision develops the working skill, keeping its existing invocation: `$just-build` in Codex or `/just-build` in Claude Code. It remains explicitly invoked. Hosting agents perform research and development; the helpers enforce recorded evidence and run bounded checks.

Two independently reproduced continuation defects are fixed. A state folder nested inside a project could change the project snapshot whenever the tracker generated a report. Continue now rejects nested/equal paths before creating directories. A standard-profile run could finish with stale Quality/Polish approvals after edits and fresh tests. Every profile now requires passing reviews bound to current files before Final Verify or handoff. `recheck` offers explicit recovery after completed Quality, preserving frozen acceptance and history.

The new read-only `diagnose --state-dir <run>` command explains missing/failed/stale checks, current approvals, output availability and suggested recovery. It executes no commands and rewrites no evidence. It returns bounded authored codes/hints rather than copying goals, command output or private notes. Independent review caught and closed misleading guidance for failed exploratory checks and malformed nested ledger errors. See [recovery instructions](../codex/just-build/references/diagnostics-and-recovery.md).

Public contracts can assert entire strict JSON values with exact types, rather than relying only on substrings. CLI checks can also hash existing scratch inputs before and after a command. Bounds, invalid encoding, duplicate keys, nonfinite numbers, links and unsafe paths are covered; old contracts keep their normalized hashes. See [contract instructions](../codex/just-build/references/behavior-contracts.md).

A fresh agent separately implemented a small stdlib JSON inspector against a specification. Its 15 subprocess tests passed, followed by all six externally authored contract steps covering exact values, input preservation, error recovery and overwrite rejection. The contract was authored before the builder started. This trial exercises the new assertion features; it is not a full tracked Just Build run and is not added to the two full-workflow examples. Its project and report are preserved with the distribution's external verification evidence.

The accompanying verification directory contains the current host-suite reports, root tooling/example checks, independent review and exact artifact verification. Historic evaluation evidence remains explicitly scoped to its source revision. Local tests do not establish real demand, best-possible ideas, uninterrupted autonomy or an actual Claude Code/hosted-CI result. No remote repository, hosted settings, release or deployment was changed. See [evaluation status](EVALUATION.md).

The expanded full helper run first reached the prior 300-second harness limit without reporting an assertion failure before cutoff. That failed report is preserved. The helper batch now permits 600 seconds and each small fixture 60 seconds; skill CI jobs allow 15 minutes including setup. Application command budgets and assertion requirements are unchanged.

Final Windows/Python 3.13.5 verification passed 222 tests per host with zero skips, 62 repository tests with no skips, and the unchanged two-example evaluation (16 project tests, 19 public cases and two integrity checks). The full helper batches finished in approximately 322 seconds each. Every delivered skill digest is checked against its fresh report during packaging. Hosted matrices and an actual Claude Code host remain unobserved.
