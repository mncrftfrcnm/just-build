# Securer — final security audit and repair

Use for **new** enhanced builds: set `"security_profile": "full"` in the acceptance plan. Historical plans without this field remain readable. Run Securer **after Quality and Human Polish, before final verification**. Delegate to a real security-focused subagent only if the host supports delegation; otherwise use an explicitly labelled `single-agent-fallback` pass. Do not pretend a role means an independent model.

1. Read `BRIEF.md`, implemented code, dependencies and actual user-exposed entry points. Identify data/trust boundaries, sensitive operations, and whether the project exposes a public network service. Review authentication/authorization, input validation, secret handling, logging, dependency/configuration risks, resource limits, retry/backoff, quota and request-rate controls. Rate limiting is appropriate for public services and external API integrations, not automatically for every offline CLI. Consider per-client/per-account budgets, 429/Retry-After, bounded work queues, and upstream provider limits.
2. Run `python3 <skill-dir>/scripts/run_tracker.py security-scan --state-dir RUN`. Read generated `SECURITY_AUDIT.md`. This is **read-only heuristic scanning**, not a penetration test and not comprehensive dependency or secret scanning. Never paste raw credentials into reports.
3. Triage findings and correct issues within the project's authorized scope. If source changed after Quality/Polish, run `recheck --state-dir RUN` and repeat both reviews. Scan the **new** source again. No passing audit may carry major/critical scan findings; document limitations and accepted minor risks.
4. If a public network endpoint exists, explicitly implement a suitable rate/quota policy and create a dedicated **bound acceptance test** that exercises enforcement (such as quota exhaustion, rejection, recovery). This test must pass in initial Verify and be rerun in Final Verify. For new full-security HTTP API builds, require `contract_profile: external-api` (see `references/behavior-contracts.md`): its frozen external contract directly observes 429, Retry-After and recovery on loopback and is rerun after polishing. For this profile the security review must use `test_label: external-contract`; older bound command-based plans remain readable with weaker evidence. This is an ordinary bounded behavioral test, **not active pentesting**. If the plan omitted the rate-limit criterion, block and start a fresh continuation run with a revised plan; completed plans cannot be silently rewritten or relabelled. Do not fake evidence or call a config string an enforcement test. For offline/local-only products record a concrete N/A rationale.
5. Record a security review using `review --role security --file review.json` after the current scan; see `examples/security-review.json`. A pass requires five substantive checks, an honest threat model and rate-limit disposition, acknowledgement of all current scan IDs, and no open major/critical items. `SECURITY_AUDIT.md` records results and limitations.
6. **Probing is opt-in, local and strictly scoped**: default `skipped-not-authorized`. Do not probe external hosts, users, accounts or third-party endpoints. Only perform bounded, non-destructive checks against the user-authorized local project when explicit scope exists and the host permits it; otherwise skip, not a blocker. Never attempt persistence, exploitation, credential attacks, denial-of-service or evasion. Record what was actually exercised, not a fictional pentest.
7. Start Final Verify only after Securer passes on the same unchanged source assessed by Quality and Polish. Re-run **all** planned checks after security changes. A post-final edit requires `recheck` and repeats Quality, Polish, Securer and final tests. Do not claim secure-by-default certification: the static scanner has false negatives/positives and delegated reviews are declarations.

For `usability_profile: novice-v1`, a Security or late Polish edit also invalidates the first-user/advocate pair. `recheck` repeats that gate inside Quality before renewed Polish and Security; it retains attempt history and the three-round limit. The frozen functional plan and external contract are preserved.

Keep the review concise and actionable. No mandatory network tooling or dependency downloads. If a finding cannot be safely fixed, mark `needs-work` and disclose the blocker rather than silently waive it.
