# Live Codex + Claude Code evaluation protocol — NOT YET EXECUTED

Do not mark Just Build as an autonomous-builder success using only its helper's synthetic tests. Run the suite independently in **fresh actual Codex and Claude Code hosts**, each with a temporary sandbox and explicitly available web search. Compare host outcomes separately, never combine them into a single pass. Save the initial request, host/version, skill revision and enabled tools, final tree, commands/results, independent evaluator outcome, elapsed wall time and human interventions. No unattended deployment or publishing.

For a CLI project, freeze a project-external `external-cli` behavior contract before implementation, then execute it in both verification phases; preserve its frozen manifest, source fingerprints and observed scenario results. This is an additional reproducible check, not an independent evaluator or sandbox. For web/API, use external browser or HTTP checks appropriate to the surface.

For each host and run, apply the same rubric: (1) independently executable public user journey; (2) meaningful invalid/empty-state check; (3) tool-observed scoped internet research during *implementation* (not only self-entered citations); (4) at least one documented implementation probe and bounded repair where needed; (5) two honest reviews and final rerun after edits; (6) clear limitations. Fail on missing artifact, fabricated research, placeholder test, unsafe unauthorized operation, or missing independently witnessed user-flow check.

- **A. Auto from blank folder:** invoke `$just-build` in Codex or `/just-build` in Claude Code with an accessible interest note and live search. Check varied discovery, traced shortlist, separately frozen A/B research, evidence comparison, actual competitors and a falsifiable advantage. Preserve valid experiment/no-build outcomes separately from build success. For a build verify source dates, implementation research and public journey/invalid-path behavior without mystery credentials. See `IDEA_EVAL_PROTOCOL.md` for cold-start and adversarial cases.
- **B. Small web app:** ask Guided New for a local-first application with real empty, loading/error and completion flows. Independently inspect browser interaction at 390px and desktop width, keyboard/focus and reduced-motion where applicable. Record screenshots or browser evidence only if tools actually produced them.
- **C. Continue an unknown existing repo:** use a fixture repo with tests, uncommitted changes and one seeded bug. Require baseline checks, preservation of dirty files, no silent dependency changes, a targeted fix and regression test, fresh reviews and test rerun.

Use a separate evaluator who did **not** author the generated project when available. Run the evaluator's test commands on a clean copy; do not ask the building agent to grade itself. Require 3/3 initial passes **per host** to advance that host to wider alpha testing; this does not imply statistically established reliability. Report raw failures and assistance required. If a host, internet or accounts are unavailable, mark that run `not run`, not `pass`.

### Additional local API security benchmark (when host permits)

In a user-authorized fresh local workspace, build a small API with a documented per-actor quota, 429/Retry-After and recovery. Freeze an `external-api` behavior contract **before** implementation approval; run it before and after Securer. Introduce one controlled defect in a disposable copy (disabled limit or missing Retry-After), confirm the contract fails, repair it, and record fresh successful output. Only send HTTP requests to the locally launched project on loopback, never public or third-party endpoints. Grade usefulness of code, source evidence, actual error handling, safe resource limits and token consumption separately from unit-test counts. This benchmark is still pending actual host execution.
